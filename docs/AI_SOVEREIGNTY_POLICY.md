# AI Sovereignty Policy — Micelia

**Version**: 1.0
**Effective (policy)**: 2026-05-24
**Status**: **declarative policy v0.1 — technical enforcement scheduled for v0.2**
**Companion to**: `docs/LICENSING_STRATEGY.md` (this policy closes amenaza A6 — tecnofeudalismo IA)

> **Honest disclosure (added in T5.4 post-review)**: The principles below are
> binding as project policy from 2026-05-24 — meaning the maintainers and
> reviewers commit to enforcing them in code review and PR acceptance. The
> *technical* enforcement mechanisms referenced in §5 (CI flag `--no-proprietary`,
> target `make sovereignty-audit`) are **not implemented yet**; they are
> scheduled for the v0.2 milestone. Until then, enforcement relies on manual
> code review. This is documented openly so consumers don't assume a stronger
> guarantee than exists.

---

## 1. Why this policy exists

Open-source code that depends exclusively on closed AI models is not actually sovereign — it merely changes the lord. If Micelia is AGPLv3 but every meaningful operation requires a proprietary API (OpenAI, Anthropic, Google), then the cooperative node is still a tenant of a corporate landlord. The licensing strategy alone cannot fix this. This policy can.

The Nodo 1 document defines Micelia as a system where "each person is a node that contributes to collective progress with AI assistance and receives basic-needs coverage in return." That contract is void if the AI assistance is rentier.

---

## 2. Hard requirements (mandatory)

These requirements are binding on every module accepted into the Micelia core (`app/`, `frontend/`, and the canonical SDK):

### 2.1 Open-weight first

Every AI capability in the core MUST be implementable with at least one open-weight model with permissive or copyleft weights license (Apache 2.0, MIT, Llama Community License, Apache-style Mistral license, Qwen license). Open-weight means: the trained model parameters are downloadable, locally executable, and redistributable under terms that permit cooperative use.

The reference open-weight stack as of v0.1:

| Capability | Reference open-weight model | License | Local-runnable |
|---|---|---|---|
| Chat / reasoning | Llama 3.1 8B / Mistral 7B / Qwen 2.5 7B | Llama CL / Apache 2.0 / Tongyi Qianwen | Yes (Ollama) |
| Embeddings | bge-m3 / nomic-embed-text | MIT / Apache 2.0 | Yes |
| Code generation | Qwen2.5-Coder / DeepSeek-Coder | Apache 2.0 / DeepSeek License | Yes |
| Speech-to-text | Whisper Large v3 | MIT | Yes |
| Vision | LLaVA / Qwen-VL | Apache 2.0 / Tongyi Qianwen | Yes |

If a new capability requires a model class with no open-weight counterpart, that capability is **NOT a core requirement** — it goes to optional modules under FSL.

### 2.2 Graceful degradation

If a node has only the open-weight stack available (no proprietary API keys configured), Micelia MUST function without errors. Features that depend on proprietary models MAY be unavailable, but the core node operations (event store, gateway, scheduler, prompt store, registry, federation) MUST work.

The test suite includes a `--no-proprietary` flag that runs all tests with proprietary backends disabled. Any module breaking this flag is non-compliant.

### 2.3 No exclusive proprietary dependency

A core module MUST NOT be implementable exclusively against a single proprietary provider. If a module integrates with OpenAI, it must also have an Ollama / Llama-compatible code path (which may be lower-quality but functional).

Exception: modules clearly marked as `# requires_proprietary: <provider>` in their docstring AND located under `app/services/proprietary/` are allowed. These modules are optional and the orchestrator must skip them gracefully if unavailable.

### 2.4 Data sovereignty of contributions

Data generated by node contributions (prompts, completions, biomarkers, training tuples) belongs to the **collective node pool** and is licensed by default under CC-BY-SA-4.0. It MAY be used to:

- Fine-tune open-weight models redistributed under the same or more permissive license
- Power Micelia retrieval-augmented systems for all nodes
- Be exported by the contributing node for personal use

It MAY NOT be used to:

- Train proprietary models whose weights are not open under terms compatible with §2.1
- Be sold to third-party AI providers as training data
- Be transferred outside the cooperative without explicit node consent

The event store schema enforces this: every node has a `data_export_policy` field defaulting to "cooperative-only".

## 3. Soft requirements (recommended)

Not binding but expected:

### 3.1 Prefer European-jurisdiction model providers when proprietary is needed

When a node opts into proprietary models for performance reasons, prefer providers under EU data jurisdiction (Mistral Large, Aleph Alpha) over US-jurisdiction providers (OpenAI, Anthropic, Google) where capability is comparable.

### 3.2 Document model dependencies explicitly

Every module that calls an LLM must declare its model dependencies in a `model_requirements:` YAML block at the top of the module, listing:
- Minimum open-weight model class (e.g. "7B parameter Llama-compatible")
- Optional proprietary upgrade (e.g. "GPT-4o for higher quality")
- Quality delta between the two (e.g. "open-weight produces 80% of proprietary quality on internal eval")

This makes the dependency graph auditable.

### 3.3 Cooperative-shared compute

When a node has spare GPU/CPU cycles, it SHOULD opt into the cooperative compute pool. Other nodes without local GPU can route inference requests through the pool. This reduces individual hardware barriers and reinforces the mycelial metaphor: nutrients flow where needed.

## 4. Anti-patterns explicitly forbidden

The following are non-compliant with this policy and any PR introducing them will be rejected:

- **Required API key**: a core module that fails to import or initialize without a proprietary API key set
- **Fine-tuning on proprietary outputs**: using outputs from GPT-4 / Claude / Gemini to fine-tune a model that is then redistributed (this often violates the provider's TOS AND it makes the resulting model derivative of proprietary work)
- **Embedding lock-in**: storing embeddings produced by a proprietary embeddings API where the model is not stable across time (forces re-embedding if the provider deprecates the model)
- **Telemetry exfiltration**: sending any node telemetry to a proprietary AI provider for any reason
- **Closed-model evals**: relying solely on proprietary models to evaluate the quality of other models (cyclical capture)

---

## 5. Enforcement

This policy is enforced through:

1. **Code review**: PRs that introduce or modify model-related code require a checklist item confirming policy compliance
2. **CI gate**: the test suite runs `pytest tests/ --no-proprietary` and fails if core tests fail
3. **Dependency audit**: `make rebrand-verify` will be extended to include a `make sovereignty-audit` target that scans for direct calls to `openai`, `anthropic`, `google.generativeai` outside `app/services/proprietary/`
4. **Annual review**: this policy is reviewed yearly by the Active Nodes; changes follow the same supermajority process as license changes (see `docs/CLA.md` §4)

## 6. Glossary

- **Open-weight model**: a model whose trained parameters are downloadable, locally executable, and redistributable under terms compatible with cooperative use. Examples: Llama, Mistral, Qwen, DeepSeek, Phi.
- **Open-source model**: stronger than open-weight — includes the training code, training data documentation, and full reproducibility. Rare. Examples: OLMo, BLOOM. Preferred when available but not required by this policy.
- **Proprietary model**: model whose weights are not redistributable. Accessible only through an API controlled by the provider. Examples: GPT-4, Claude, Gemini, Grok.
- **Open-weight stack**: the set of open-weight models that together cover the AI capabilities Micelia needs. As of v0.1: Llama 3.1 8B + bge-m3 + Whisper Large v3 + LLaVA, all runnable via Ollama on a Mac Studio.
